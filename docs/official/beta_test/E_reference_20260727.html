📐 Cost Function (V5)

Per-Case Cost Formula

Cost = OutlineArea + α × TotalWireLength
        + OverflowPenalty + FTPenalty
        + λft × IllegalFTDeltaArea
        + γ × EdgeLocationPenalty
        + δ × runtime_sec × √OutlineArea

OverflowPenalty（分段 piecewise）

overflow_rate = ChannelOverflowTotal / TotalChannelCapacity

if overflow_rate ≤ threshold:
  OverflowPenalty = βlin × overflow_rate × OutlineArea

else:
  OverflowPenalty = βlin × threshold × OutlineArea
                 + βtail × √(overflow_rate − threshold) × OutlineArea

FTPenalty

FTPenalty = βft × FTAreaExcess
where FTAreaExcess = max(0, Σft_area_by_block − OutlineArea)

IllegalFTPenalty（依 A1：扣分項，非 hard-fail）

IllegalFTPenalty = λft × IllegalFTDeltaArea
where IllegalFTDeltaArea = Σ(所有非法 FT block 的 delta_area)

MACRO/EDGE block 作為 feedthrough（出現在 PATH 中間）依 A1 為扣分項，不判定 FAIL。
懲罰量 = 每個非法 FT block 的 FT 面積膨脹量之和 × λft。
非法 FT 比「合法 FT 面積超額」嚴重——λft = 10 約為 βft 的 3 倍。

EdgeLocationPenalty

EdgeLocationPenalty = Σ(所有違規 EDGE block 的偏移距離(um))
1 um offset = γ × 1 um² penalty

RuntimePenalty

RuntimePenalty = δ × runtime_sec × √OutlineArea
用 √OutlineArea 正規化：同一 runtime 對大 case 影響較小。

未完成懲罰 (Incompletion Penalty)

每個未 PASS 的 case：
  incompletion_penalty += worst_cost_of_case × M

FAIL case 的 runtime penalty：
  fail_runtime_penalty += δ × max_runtime_of_case × √median_outline_area_of_case

total_cost = base_cost + incompletion_penalty + runtime_penalty (含 fail_runtime_penalty)

WireLength 計算（Guiding Point 定義）

依 A41（Figure 6）：兩個 channel 之間有一段重疊的連接邊界時，路徑必須通過該重疊邊界的中點。

Guiding Point = 重疊邊界線段的中點（midpoint of overlapping segment），
而非兩矩形整個 edge 的中心平均值。

轉折點（同 rect 不同 edge）= rect 對應角落的交點。

Channel Demand 計算

依 A5：每條 net 穿過一個 channel 計1次 demand（而非 entry+exit 各計一次）。

直穿（opposite edge，如 edge1→edge3）：計 1 次水平 demand。
轉向（corner turn，如 edge1→edge2）：計 1 次水平 + 1 次垂直 demand。

容量：水平 = 25 × channel.height，垂直 = 25 × channel.width。

📏 座標精度與進位規則（A34/A39）

⚠ 核心原則（最重要的一句話）

Checker 全程使用原始浮點座標——幾何拓樸判斷和成本計算都不做進位。
Spec A34「長度無條件進位」和 A39「面積四捨五入」不在 checker 中實作； 所有長度、面積一律以原始浮點值計算與比較。
為什麼？
Spec A34/A39 要求「長度無條件進位到整數、面積四捨五入到小數點後第二位」， 但這條規則在實作上有極大的陷阱——不可以對每個座標分量各自進位後再組合， 因為那會破壞原本對齊的相鄰關係，造成假性違規（見下方例子）。
為確保一致性，本 checker 選擇全程不進位——幾何檢查和成本計算看到的是同一組數字。

Step 2：幾何拓樸判斷（相鄰 / 重疊 / outline 超出）

假設另一個 block BLK05 的左邊界恰好在 x = 1396.901159（與 BLK02 右邊界對齊）。

❌ 如果各自進位再判斷：
BLK02: ceil(x) = 864, ceil(w) = 534 → 右邊界 = 864 + 534 = 1398
BLK05: ceil(x') = 1397 → 左邊界 = 1397

實際差距 = |1396.901159 − 1396.901159| = 0 ← 本來就對齊！
✅ Checker 的正確做法（用原始浮點）：
BLK02 右邊界 = x + w = 1396.901159（不進位）
BLK05 左邊界 = x' = 1396.901159（不進位）
|1396.901159 − 1396.901159| = 0 < EPS=3 → ✅ 相鄰通過
結論：各自進位會讓原本對齊的邊界產生 1~2 um 誤差。 若這個誤差累積超過 EPS=3um，原本合法的解會被誤判為 ROUTING_OPEN 或 BLOCK_OVERLAP。

Checker 不會做的事情（放心）：
  • Checker 不會對 block 的 x, y, w, h 分別進位後再判斷相鄰 / 重疊
  • Checker 不會先對 outline W, H 進位再算 OutlineArea
  • Checker 不會把浮點累積誤差（如 y+h 其實比 H 多 0.000001）判定為 violation

  • Checker 不會對 WireLength 或任何 penalty 項做進位
❓ 常見疑問

Q1：Spec 寫「長度無條件進位」，為什麼 checker 不實作？
A：因為對每個座標分量(x, y, w, h)各自進位，會在求和時(y+h, x+w)產生累積誤差， 破壞原本對齊的幾何關係。Spec 的進位規則適用於「單一長度值」（如一條線段長度）， 不適用於「逐分量進位後再組合」。為保證一致性，checker 選擇全程不進位。

Q2：我輸出整數座標可以嗎？
A：可以。如果你的 solver 內部使用整數算術，直接輸出整數即可， 不需額外做 ceil/round。Checker 會正確處理整數與浮點輸入。

Q3：我輸出浮點座標可以嗎？
A：可以。但請確保相鄰 block 的邊界在實際浮點值上對齊（誤差 ≤ 3um）， 而非進位後碰巧對齊。Checker 容差 EPS=3um 可吸收浮點計算的微小噪音。

Q4：面積四捨五入（A39）呢？
A：Checker 的 OutlineArea = W × H（浮點乘法），不做四捨五入。 所有成本項（含 penalty）均為浮點值，最終 cost 也是浮點數。 排名用完整浮點值比較，不做進位或四捨五入。
