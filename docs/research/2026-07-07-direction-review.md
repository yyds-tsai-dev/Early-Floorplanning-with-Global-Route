# Direction Review — 2026-07-07 (post-P0/P1/P3, P2 in flight)

Purpose: re-derive the optimization priorities for `Cost = OutlineArea + α×TotalWireLength` from (a) a fresh read of the official spec (`docs/official/E_20260608.pdf`) and Q&A (`docs/official/E_QA_20260618.pdf`), (b) the measured results of P0/P1/P3 and the in-flight P2 (`.superpowers/sdd/progress.md`, phase reports), and (c) an external primary-source sweep (contest site, papers, open-source repos — companion file: `docs/research/2026-07-07-external-techniques-survey.md`). Extends `docs/research/2026-07-06-cost-reduction-strategy.md`; supersedes its P4/P5 ordering. Architecture (`docs/superpowers/specs/2026-06-14-long-term-placement-engine-design.md`) is unchanged.

## 1. Verdict on the current direction

**The architecture is validated — keep it.** SA over pluggable engines (sp/bstar/hybrid) + two-tier eval + exact router is what all four external research reports independently converge on for n<50, no-GPU, custom-legality problems; nothing found this round argues for a rewrite. The measured gaps are not representational; they are (i) unfinished P2, (ii) search-compute utilization, (iii) proxy fidelity, and (iv) one missing joint-optimization coupling (soft-block shape ↔ channel capacity).

## 2. Evidence base (what changed since the 2026-07-06 strategy doc)

1. **P1+P3 landed with honest sweeps.** Outline shrink works (11/15 rows, up to −33% outline_area) and respacing kills overflow where an axis has slack (case1 score −55.9%/−48.5%/−11.8%; case2 bstar/hybrid −29.5%/−25.5%). **10/15 rows are axis-locked** (case2/sp, all case3, all case4): core x-extent pinned at MAX, spacing cannot create capacity. (p1-task-8-report, p3-task-7-report)
2. **Internal score is now ~entirely overflow penalty on cases 1–4** (overflow 26k–205k µm² × 1e6 vs true cost ≈ 1e7–1e8). The official deduction formula is *unpublished* (QA A1: "依 overflow 程度比例扣分") — so contest-safe submissions must reach **0 overflow / 0 mismatch**, and internal graded weights exist only to steer search. Unchanged conclusion, now with sharper numbers.
3. **Once overflow is gone, α·WL ≈ or > OutlineArea on the big cases** (α=0.2: case2 0.2·WL≈4.2–5.4e7 vs area 4.2e7; case4 ≈6.7e7 vs 3.8e7, and P1 shrank areas further). WL optimization is not a second-class citizen after P2.
4. **All published numbers are single-run, seed=1, iters=2000.** Engine winners differ per case (e.g. case0: bstar WL 7.1e6 vs sp 11.7e6). Nothing exploits the official runtime budget: **all testcases within 2 hours** (spec §4), ~10 min/case at the promised 12 public cases. Measured baseline runtime, hybrid iters=2000: **all 5 public cases finish in ≈23 s total** (case4 worst at 13.2 s; §6 table) — **~45×–300× of the official budget is unused**.
5. **Official sources: no changes since 2026-06-18** (site checked 2026-07-07: news entry that day covers problems A/B/D only; spec 06/08, Q&A + testcases 06/18; no evaluator, no alpha results for E, no public competitor repos found). Local CSVs verified to BE the 06/18 fixed versions (case1 BLK11 AREA=267200=334×800; FT first tier `<=3000`). Beta 2026-07-24: +7 public cases, BLK<50 (QA A1.3), nets ≤ 500k (A24).
6. **Spec-freedom audit (fresh re-read):** all major freedoms are either exploited or in flight — outline shrink + declared-outline scoring (A13/A25: done P1), same-side multi-LOCATION = OR / cross-side = corner AND (A35.2: verified correct in `edgeRectLegal`/`satisfiesEdgeLocations`), PORT EDGE multi-value = any-of (A35.3: verified `portAllows`), bundle splitting (A4.2/A6: fixed 8×1000 chunks today; P2 T3 makes it demand-adaptive), direct-abutment zero-channel/zero-WL (A31: eval-side done P0; **search-side untapped** → P4b/P4d), FT marginal pricing (P2 T0–T2 done, T3–T7 pending). Only untouched freedom: **outline aspect ratio** as a search dimension (P1 Q1, still open → P4f pilot).

## 4. Do-not-repeat list (rejections that stand, with sources)

- **RL / GPU anything** — no GPU in judging env (QA A1.4); n<50 can't amortize learning (strategy doc §3.3; both GPT reports concur).
- **Monotone-staircase / HGR-style channels** — spec fixes channel extraction to vertical slicing (spec §2 + reference code; strategy doc §3.3).
- **Corner stitching / SCB-tree as data structure; vEB FAST-SP decode** — O(1)/O(n log n) machinery irrelevant at n<50 µs-scale decode (strategy doc §3.3). Mine FTAFP's slack-move *ideas* only.
- **Flora engine** (zero-whitespace) — conflicts with channel supply; keep only the whitespace-absorption idea (gemini v2 "fatal weakness"; strategy doc §3.3).
- **Hierarchical clustering / multilevel (Hier-RTLMP-style)** — n<50 (gpt v1 #2 demoted; digest).
- **Outline as an SA gene** — shrink-wrap computes the closed-form optimum per decode (p1-design §1.1). P4f explores *targets*, not genes.
- **Respace inside the SA hot loop** — needs routed placement; blows runtime (p3-design §5).
- **Mismatch-decrease-only FT acceptance** — trades legality for mismatch (P0 final review adjudication).
- **Linear-grow shrink search** — replaced by bisection (P1 T4.5, measured 0.16% vs 7% shrink).
- **Peripheral outline growth to relieve inter-core congestion** — falsified (P1 T8.1: anchorAtOutline only re-legalizes edge blocks; 14/15 rows unchanged).

## 5. Risks & watch items

- **Unknown official overflow/mismatch deduction scale** → final submissions target 0/0; graded weights are search-internal only. Revisit if an evaluator appears.
- **QA A3.1 vs A3.2 capacity banding tension** → keep the conservative per-direction *sum* reading (never under-penalizes vs the official reading; may over-penalize → we may leave a little capacity unused). Revisit only with an official evaluator.
- **Thread policy unstated** → default single-thread; sequential multi-start already captures most of the 2h budget. Worth an official Q&A question.
- **α on hidden cases unknown** (public = 0.2; QA A35.5 says testcase-defined) → everything stays parameterized on `problem.alpha`; the portfolio adapts naturally.
- **Beta 2026-07-24 (+7 public cases)** → immediately re-run the 15-row (then 36-row) sweep; prefer robustness (portfolio) over per-case parameter tuning; recalibrate priorities if the new cases break the axis-locked pattern.
- **`channelBounds` wrong-pair attribution under stamp/routing disagreement** (P3 final review minor) → becomes load-bearing if P4c consumes channelBounds; re-check then.

## 7. External survey pointers (details in companion file)

- **Contest**: nothing new for E since 06/18; alpha results exist for B/D only; no evaluator; no competitor repos discoverable.
- **Genuinely new techniques found, and where they were absorbed above**: SDS slack-driven shaping (ISPD 2012) → P4c backbone; diversity-aware elite pool (Jaradat 2016) + VAL wall-clock restart schedule (Cicirello 2017) → P4a; MAB move-type selection (GECCO 2008, experiment-grade) → P4d; PathFinder-at-global-routing-granularity citations (Roy & Markov 2008, NTHU-Route 2.0) → P2 T4 reference; GP/SOCP + Per-RMAP convex shaping → P5 escalation.
- **Survey's negative results worth keeping** (§Top-10 "not recommended"): FAST-SP decode speedup, MB*-tree, min-cost multicommodity flow / Lagrangian pricing (same math as PathFinder's principled cousin — prefer the cheap approximation), BEAR channel ordering, CSF/FFA-CD analytical engines (hard-blocks-only or representation-mismatched), parallel tempering (evidence: independent chains do as well).
- **Minable code**: OpenROAD `mpl` `SimulatedAnnealingCore` (BSD-3) — pattern for pluggable weighted cost terms; `grt` RUDY — fallback congestion proxy; `mirkat1206/Sequence-Pair-Floorplanner` (MIT) — FAST-SP reference (not needed at n<50); `johnnyhuang1007/iccad-2023-problem-D` (MIT) — soft-block/fixed-outline tricks lead (src/doc unread; repo warns about `double` coordinates → cross-check our `model.hpp` kEps discipline when reading).
